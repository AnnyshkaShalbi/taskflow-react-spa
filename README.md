# TaskFlow

SPA-трекер задач и привычек для удалённых команд. Канбан-доска, повторяющиеся привычки, графики прогресса и шаринг досок — всё на клиенте с имитацией API через MSW.

## ✨ Возможности

- 📋 Канбан-доска с drag-and-drop, адаптированная под мобильные устройства
- 📱 Адаптивная вёрстка: мобилка, планшет, десктоп
- 🔁 Трекер повторяющихся привычек
- 📊 Графики прогресса
- 👥 Шаринг досок с коллегами
- 🔐 Авторизация (имитация через MSW) + быстрый вход под демо-пользователями
- 🌗 Светлая и тёмная темы
- 🇷🇺 Мультиязычность

## 🔑 Демо-доступ

На странице входа можно войти в один клик под одним из демо-пользователей. Роли разные, так что видно, как работают совместный доступ и права:

| Пользователь | Роль | Что попробовать |
| --- | --- | --- |
| Анна Шалбуз | Владелец досок | Пригласить и удалить участников доски |
| Иван Петров | Своя доска + участник чужих | Переключаться между своей и общей доской |
| Мария Сидорова | Только участник | Видит общую доску, но не может управлять участниками |

Можно войти и через форму: `anna@taskflow.dev` / `password123` (у всех пользователей одинаковый пароль).

## 🏗 Архитектура

Проект построен по методологии **[Feature-Sliced Design](https://feature-sliced.design/)**.

```
src/
  app/        # точка входа, провайдеры, роутер, глобальные стили
  pages/      # страницы под маршруты
  widgets/    # самостоятельные UI-блоки (Header, KanbanBoard)
  features/   # пользовательские сценарии (create-task, toggle-habit)
  entities/   # бизнес-сущности (task, habit, user, board)
  shared/     # переиспользуемое: ui, lib, api, config, types
  mocks/      # MSW-хендлеры
```

**Правило импортов:** слой может импортировать только из слоёв ниже себя. Внутри слоя — только через `index.ts` (public API).

## 📱 Канбан-доска на мобильных устройствах

На телефоне перетаскивать карточки неудобно: жест неочевиден, палец закрывает карточку и цель, а до дальней колонки нужно долго тянуть. Поэтому мобильная версия доски устроена так: drag-and-drop остаётся инструментом для опытных пользователей, а каждое действие можно сделать и без него.

| Проблема | Решение |
| --- | --- |
| Три колонки не помещаются на экране | Колонки идут лентой, которая листается свайпом и останавливается ровно на колонке, как в Trello и Jira. Край следующей колонки выглядывает, подсказывая, что дальше есть ещё |
| Свайп по карточке перетаскивал её вместо прокрутки | Перетаскивание на тачскрине начинается только по долгому нажатию, обычный свайп просто листает |
| Перетаскивание неочевидно и неудобно | У каждой карточки есть меню «⋯» → «Переместить в…»: статус меняется в два тапа |
| Непонятно, где ты на доске | Над лентой закреплены табы с количеством задач. Тап переносит к колонке, а при свайпе активный таб переключается сам |
| Долго тянуть карточку в дальнюю колонку | Карточку можно бросить прямо на таб, например «Готово» |
| Непонятно, что карточка «взята» | Телефон коротко вибрирует при захвате карточки и при наведении на таб (на Android), а сама карточка визуально «приподнимается» |

На десктопе всё как привычно: три колонки рядом и перетаскивание мышью.

*Под капотом:* @dnd-kit с отдельными сенсорами для мыши и касаний и своей логикой определения цели, CSS scroll-snap, Vibration API.

## 🚀 Запуск

```bash
npm install
npm run dev
```

Приложение откроется на `http://localhost:5173`.

**Демо-режим.** Бэкенда у проекта нет, API имитирует MSW. В dev-режиме моки включены всегда. В production они включаются флагом `VITE_DEMO_MODE=true`, он уже задан в `.env.production`, поэтому собранное приложение работает на любом статическом хостинге без сервера. Флаг также управляет блоком демо-входа: если сборка без демо-режима, ни моки, ни демо-пароли в неё не попадут.

**Сборка:**
```bash
npm run build
npm run preview
```

**Качество кода:**
```bash
npm run lint
npm run format
```
